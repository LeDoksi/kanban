# Канбан: вход и установка как приложение

**Часть более крупного бэклога** («план №3») — фидбек владельца с
живого использования доски. Бэклог разбит на независимые суб-проекты;
это спека на **суб-проект 3, последний в этой серии**. Суб-проекты 1
(«Задача и эпик как полноценные сущности») и 2 («Навигация и структура
проекта») уже реализованы и смержены.

**Родительская спека:** `docs/superpowers/specs/2026-09-11-kanban-design.md`.

## Контекст и уточнение задачи

Изначальный тикет (KAN-50) звучал как «слетает вход» — при проверке
выяснилось, что у владельца сессия держится нормально (supabase-js
хранит её в localStorage и обновляет неделями); слетает только у
браузерного инструмента агента между отдельными CLI-сессиями — это
свойство изолированного инструмента, не баг приложения, чинить нечего.

Настоящая задача — KAN-51: **magic-link не работает для сайта,
установленного на iPhone как приложение** («На экран «Домой»»). На iOS
ссылка из письма открывается в Safari, а не в уже установленном
standalone-приложении — у них разное хранилище, даже при одном движке.
Плюс самой возможности установки сейчас нет — ни манифеста, ни иконок.

## Цель

Сайт можно поставить на экран «Домой» на iPhone с нормальной иконкой, и
войти в него можно изнутри самого приложения — без перехода в Safari.

## A. PWA — манифест и иконки

**Файлы:**
- `web/public/manifest.webmanifest` — новый.
- `web/public/icons/apple-touch-icon.png` (180×180), `icon-192.png`,
  `icon-512.png` — новые, генерируются скриптом (см. ниже), не пишутся
  руками.
- `web/index.html` — модифицируется: ссылки на манифест/иконку, мета-теги.
- `web/package.json` — `sharp` в `devDependencies` (только инструмент
  генерации иконок, в продакшен-бандл не попадает).

**Манифест** (пути — с `/kanban/` явно, этот файл не проходит через
сборку Vite и не разворачивается автоматически, в отличие от `index.html`):

```json
{
  "name": "Канбан",
  "short_name": "Канбан",
  "start_url": "/kanban/",
  "scope": "/kanban/",
  "display": "standalone",
  "background_color": "#17171a",
  "theme_color": "#17171a",
  "icons": [
    { "src": "/kanban/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/kanban/icons/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

**Иконка** — монограмма «K», тёмный фон (`#1a1a18`, тот же тон, что
`--color-ink` в светлой теме сайта), белая буква. Один и тот же SVG,
растеризуется в три размера через `sharp` (Node-скрипт, запускается
один раз при реализации — не часть рантайма приложения):

```ts
const svg = (size: number) => `
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${size} ${size}">
  <rect width="${size}" height="${size}" fill="#1a1a18"/>
  <text x="${size / 2}" y="${size / 2}" font-family="system-ui, sans-serif"
        font-size="${size * 0.55}" font-weight="600" fill="#ffffff"
        text-anchor="middle" dominant-baseline="central">K</text>
</svg>`;
```

**`index.html`** — добавить в `<head>`:
```html
<link rel="manifest" href="/kanban/manifest.webmanifest" />
<link rel="apple-touch-icon" href="/kanban/icons/apple-touch-icon.png" />
<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="theme-color" content="#17171a" />
```

Офлайн-режим и service worker сознательно не делаются — задача
«поставить иконку и открывать без адресной строки», не «работать без
интернета». Доска и так ничего не показывает без Supabase.

## B. Вход — код из письма вместо ссылки

**Файлы:** `web/src/App.tsx` (компонент `SignIn` переписывается).

Сейчас: `signInWithOtp({ email, options: { emailRedirectTo } })` →
экран «ссылка ушла на email». Меняется на: `signInWithOtp({ email })`
(без `emailRedirectTo` — ссылка в верификации больше не участвует) →
экран с полем «код из письма» (6 цифр, `inputMode="numeric"`,
`maxLength={6}`) → по кнопке `sb.auth.verifyOtp({ email, token: code,
type: 'email' })`.

При успехе `verifyOtp` сам устанавливает сессию — `App.tsx`'s
существующий `onAuthStateChange`-подписчик подхватывает её без
изменений. При ошибке (неверный/просроченный код) — тот же `error`-стейт,
что уже есть в компоненте, с текстом ошибки Supabase.

Работает одинаково что в обычном браузере, что в установленном на
экран «Домой» приложении — весь процесс входа происходит внутри одной
открытой страницы, без внешнего перехода, поэтому разница между
Safari-вкладкой и standalone-режимом для этого потока не имеет
значения.

## C. Обязательный ручной шаг — шаблон письма

Supabase по умолчанию не печатает код в письме, только ссылку —
`verifyOtp` при этом продолжит работать (токен существует всегда), но
владельцу нечего будет ввести, пока шаблон не показывает `{{ .Token }}`.

Через доступные инструменты (SQL-миграции, `execute_sql`) шаблоны писем
не редактируются — это настройка вне схемы базы. Ручной шаг:
Supabase Dashboard → Authentication → Email Templates → **Magic Link** →
в тело письма добавить `{{ .Token }}` (например: «Твой код: {{ .Token }}»).
Без него функциональность не работает — шаг обязателен, не опционален.

## Обработка ошибок

Тот же паттерн, что уже в `SignIn`: `error`-стейт, показ строкой под
формой. Пустой код на кнопке «Войти» не отправляется (валидация перед
вызовом, как уже сделано для пустого email).

## Тестирование

Ничего для юнит-тестов — оба изменения (вёрстка форм, вызовы Supabase
auth) требуют живой проверки: реальное письмо, реальный код, реальная
установка на iPhone. Global Constraint «тесты только на чистые функции»
не нарушается — здесь чистых функций не появляется.

## Глобальные ограничения (унаследованы из родительской спеки)

- Тарифы: только бесплатные — `sharp` не добавляет платных сервисов,
  Supabase Auth email — бесплатный тариф уже используется.
- Доступ: RLS не меняется, эта спека не трогает данные вообще, только
  форму входа и статические файлы.
- Сервисный ключ Supabase никогда не попадает в репозиторий и в
  браузер — не затрагивается, `verifyOtp` идёт через анонимный ключ,
  как и весь остальной веб-клиент.
- Язык: комментарии в коде, тексты интерфейса — по-русски.
- Цвет несёт смысл. Иконка и `theme_color` используют существующий тон
  `--color-ink`/`--color-ground` — новых цветов не заводим.
