# Канбан: навигация и структура проекта

**Часть более крупного бэклога** («план №3») — фидбек владельца с первого
живого использования доски. Бэклог разбит на независимые суб-проекты; это
спека на **суб-проект 2**. Суб-проект 1 («Задача и эпик как полноценные
сущности») уже реализован и смержен — см.
`docs/superpowers/specs/2026-09-14-kanban-task-epic-entities-design.md`.
Суб-проект 3 («Вход и PWA») получит свою спеку отдельно.

**Родительская спека:** `docs/superpowers/specs/2026-09-11-kanban-design.md`
(модель данных, RLS, MCP-инструменты, технический стек — не повторяется
здесь).

Не входит в эту спеку (обычные баги/полировка, чинятся отдельно, без
брейншторма): KAN-40, 41, 42, 53, 54 (drag/визуал), KAN-35..39 (техдолг
плана №2), KAN-50/51 (авторизация/PWA — суб-проект 3).

## Цель

Сейчас: проект выбирается выпадающим списком в шапке (визуально
«стрёмно», по словам владельца), экран «Все проекты» существует отдельно
и еле похож на кнопку, создание проекта просит 5 полей вручную и путает
(«слаг», «префикс» непонятны, не генерируются). Цель — заменить это одной
понятной шторкой навигации и формой создания в одно поле.

## `ProjectDrawer.tsx`

Выезжающая слева панель (`fixed inset-y-0 left-0`, затемнение фона,
Escape/клик по фону закрывает — тот же визуальный язык, что у модалок
`TaskModal`/`EpicModal`, только выезжает сбоку, а не по центру).

Содержимое — перенос текущей логики `AllProjects.tsx`: список проектов
(не архивных, `order('position')`), у каждого — имя, короткое обрезанное
описание (`truncate`), `done/total`, `N ждёт` если есть задачи в
`waiting`. **Клик по строке** = `setCurrent(id)` и закрытие шторки —
никакого разворачивания описания на месте (владелец явно просил не
двигать список при просмотре описания — полное описание живёт в другом
месте, см. ниже).

Кнопка «Новый проект» — вверху списка. Открывает форму `NewProject`
прямо внутри шторки (не отдельной модалкой поверх).

**Ускорение загрузки** (жалоба на старый экран — заметно долгая
подгрузка): текущий код тянет `sb.from('items').select('*')` без единого
фильтра — все колонки всех задач всех проектов, фильтрация на клиенте.
Меняется на `select('project_id, status, archived_at')` — те же строки,
на порядок меньше данных по сети. Полноценная агрегация на стороне базы
(RPC/view) — overkill для личного проекта такого масштаба, не делаем.

## `NewProject.tsx` — упрощённая форма

Одно обязательное поле — **имя**. Слаг и префикс генерируются
автоматически по мере ввода (тот же принцип, что уже используется в
`NewTask.tsx` для угадывания типа: поле показывает сгенерированное
значение, но помечается «тронутым» при ручной правке и с этого момента
перестаёт обновляться от имени). Описание и путь к папке остаются
необязательными полями, как сейчас.

**Транслитерация** (кириллица → латиница, для слага/префикса):

```ts
const TRANSLIT: Record<string, string> = {
  а: 'a', б: 'b', в: 'v', г: 'g', д: 'd', е: 'e', ё: 'e', ж: 'zh',
  з: 'z', и: 'i', й: 'y', к: 'k', л: 'l', м: 'm', н: 'n', о: 'o',
  п: 'p', р: 'r', с: 's', т: 't', у: 'u', ф: 'f', х: 'h', ц: 'c',
  ч: 'ch', ш: 'sh', щ: 'sch', ъ: '', ы: 'y', ь: '', э: 'e', ю: 'yu',
  я: 'ya',
};

export function slugify(name: string): string {
  const translit = name.toLowerCase().split('').map(ch => TRANSLIT[ch] ?? ch).join('');
  return translit
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '');
}

export function prefixify(slug: string): string {
  return slug.replace(/-/g, '').slice(0, 3).toUpperCase();
}
```

`slugify` работает и на латинские имена без изменений (символы не из
карты проходят как есть, затем не-`[a-z0-9]` схлопывается в дефис —
пробелы, знаки препинания и т.п.). `prefixify` берёт первые 3 буквы уже
готового слага (без дефисов) и переводит в верхний регистр — пример из
текущего плейсхолдера формы (`family-app` → `FAM`) воспроизводится этой
же формулой.

Коллизии слага/префикса с уже существующим проектом не проверяются на
клиенте заранее — при реальной коллизии сработает уникальное ограничение
в базе, ошибка покажется как обычно (`err`-стейт), поля остаются
редактируемыми, владелец поправит вручную. Не усложняем ради редкого
случая у одного владельца с несколькими проектами.

## Описание проекта в шапке доски — клик-и-редактируй

Текущий код в `Board.tsx`:
```tsx
{currentProject?.description && (
  <span className="text-sm text-(--color-muted)">
    {currentProject.description}
  </span>
)}
```
Заменяется на тот же паттерн инлайн-редактирования, что уже есть у
задачи (`TaskModal`) и эпика (`EpicModal`): клик по тексту превращает
его в `<textarea>`, blur/Enter сохраняет через `update({description})`
в таблицу `projects`; если описания нет — плейсхолдер «описание — клик,
чтобы добавить», консистентно с уже принятым языком интерфейса.

Это решает поднятый владельцем вопрос «где смотреть/редактировать полное
описание, не разъезжаясь со списком проектов»: полное описание живёт на
экране доски (после переключения), шторка остаётся чистым списком для
переключения — они физически разные экраны, друг на друга не влияют.

## Обработка ошибок

Тот же паттерн, что везде: `err`-стейт, `setErr(error.message)`, показ
строкой. Ничего нового не вводится.

## Тестирование

`slugify`/`prefixify` — чистые функции, юнит-тесты
(`web/test/slug.test.ts` или расширение существующего файла с похожей
ролью), тот же принцип, что у `position.test.ts`/`epics.test.ts`. Всё
остальное — живая проверка на реальном сайте, без моков.

## Глобальные ограничения (унаследованы из родительской спеки)

- Тарифы: только бесплатные — эта спека не добавляет новых сервисов.
- Доступ: RLS остаётся единственной проверкой прав, новых сущностей без
  политики не заводим — `ProjectDrawer`/`NewProject` работают через уже
  существующую политику на `projects`.
- Сервисный ключ Supabase никогда не попадает в репозиторий и в браузер
  — этот суб-проект не трогает MCP-сервер (`mcp/`) вообще.
- Тесты — только на чистые функции (`slugify`, `prefixify`). Компоненты
  веб-интерфейса — живьём, без моков.
- Язык: комментарии в коде, тексты интерфейса и сообщения коммитов — по-русски.
- Цвет несёт смысл. Новые элементы используют уже существующие токены —
  новых цветов не заводим.
