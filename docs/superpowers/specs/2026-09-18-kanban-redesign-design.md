# Канбан: визуальный редизайн (KAN-94)

**Дата:** 2026-09-18
**Статус:** спека согласована, реализация не начата

## Цель

Полный визуальный и интеракционный редизайн `web/` — того же самого приложения, которое ведёт эту доску. Сайт должен остаться таким же полезным, но стать приятным и удобным «в лучших традициях современного дизайна»: типографика, палитра, кнопки, анимации, переходы. Поведение (realtime, drag-and-drop, позиционирование карточек, RLS-запросы, данные) не меняется — это редизайн визуально-интеракционного слоя поверх существующей логики.

Аудит кода (мёртвый код, неработающее) сознательно вынесен из этой задачи в отдельную карточку **KAN-95** — редизайн не должен путать «правим дизайн» коммиты с «чиним баг» коммитами.

## Вне охвата

- Схема Supabase, MCP-сервер (`mcp/`), backend-логика.
- Аудит мёртвого кода и починка багов — KAN-95.
- Новый веб-шрифт: личный инструмент на GitHub Pages, лишняя загрузка не окупается — остаёмся на системном шрифте.
- Параллельная (v2) реализация: продукт личный, с одним владельцем — держать две версии одновременно чистый оверхед.

## Палитра

Текущий принцип «цвет несёт смысл и только его» (статус `wait`/`danger` цветной, всё остальное монохром) пересматривается. Меняется:

- **Контраст.** Вместо плоского серого-на-сером (`#ffffff`/`#1a1a18` со средне-серым `--color-muted`/`--color-line` между ними) — более глубокий контраст: тёплый почти-белый фон и почти-чёрные чернила в светлой теме. В тёмной — заметная ступенька яркости между `ground` и `panel`, чтобы карточка читалась без явной рамки.
- **Акцент.** Один акцентный цвет вместо нейтрального чёрного на основных кнопках. Тёплый янтарно-оранжевый (сейчас смыслово занят под `wait`) становится акцентом бренда целиком: «ждёт тебя», главное действие, активные/фокус-состояния — вместо `bg-(--color-ink)` на кнопке «Новая задача».
- `danger` остаётся отдельным красным, не смешивается с акцентом.

Итог: 1 акцент + красный + монохромная база, вместо текущих 2 семантических цветов + монохром.

## Типографика

Системный шрифт (`ui-sans-serif, system-ui, sans-serif`) остаётся — платформенный стек, без дополнительной загрузки. Вводится осознанная шкала вместо разрозненных `text-sm`/`text-xs`/`text-[11px]` по всему коду: 4 уровня (заголовок секции, тело карточки, мета/лейбл, микро-подпись), каждый с последовательным весом и трекингом.

## Motion

Добавляется зависимость **`motion`** (актуальный пакет, бывший `framer-motion`; в React — импорт из `motion/react`). Роли:

1. **Layout-анимация карточек.** При смене статуса/пересортировке карточка плавно едет на новое место, а не прыгает мгновенно. Сейчас это отчасти покрывает CSS-transition из dnd-kit только во время активного драга — после `onDragEnd` и `reload()` карточка появляется на новой позиции без анимации.
2. **Модалки и шторка.** `TaskModal`, `CreateModal`, `EpicModal`, `ProjectDrawer` получают вход/выход через spring вместо мгновенного появления/исчезновения.
3. **Свайп на карточке.** Ручная арифметика `touchStartX`/`dragX` в `Board.tsx` заменяется на `motion`'ный drag с настоящей инерцией и пружинным возвратом при непройденном пороге. `swipe.ts` остаётся чистой функцией (`swipeTarget`/`swipePreview`/`SWIPE_THRESHOLD`) — меняется только источник координаты, не логика порога.

## Общие примитивы (`web/src/ui/`)

Маленький слой, не фреймворк — три компонента, устраняющие текущее дублирование:

- **`Button`** — варианты `primary` (акцентная заливка — «Новая задача»), `secondary` (панель+бордер — «Проекты», выбор статуса), `ghost` (текст без фона — «архив», «ещё N»). Сейчас — 5+ независимых копий похожего `className` по файлам.
- **`Sheet`** — общий каркас модалки/шторки: оверлей, контейнер, `motion`-анимация входа/выхода, закрытие по Esc/клику вовне. Сейчас каждая из `TaskModal`/`CreateModal`/`EpicModal`/`ProjectDrawer` реализует это самостоятельно.
- **`Card`** (стилевая обёртка, не карточка задачи) — общий стиль панели (фон/радиус/тень) для карточки задачи и её drag-превью. Сейчас `CardPreview` в `Board.tsx` — копия разметки `Card`.

Специфичная логика (drag-and-drop, свайп, чек-листы, realtime-подписки) остаётся в текущих компонентах-владельцах — примитивы только про внешний вид и базовые состояния (открыт/закрыт, наведён/в фокусе/нажат).

Подход: сначала примитивы, потом экраны на них (а не редизайн каждого файла на месте с сохранением дублирования) — это устраняет уже видимое расхождение в деталях между пятью похожими кнопками и четырьмя похожими модалками, не добавляя абстракции сверх того, что уже просится наружу.

## Экраны

- **Доска/колонки** (`Board.tsx`) — шапка колонки с более ясной иерархией (счётчик как отдельный чип, не голая цифра рядом с текстом), ровнее сетка/отступы между колонками. Группировка по эпику остаётся, рамка группы — по новому радиусу/цвету.
- **Карточка** (`Card` в `Board.tsx`) — свайп на моушен-драге, бейджи «баг»/«долг» через акцентную/danger-палитру, реальные hover/focus-visible состояния (сейчас их нет вообще — заодно доступность, не только внешний вид).
- **Модалки** (`TaskModal`, `EpicModal`, `CreateModal`) и **шторка** (`ProjectDrawer`) — переезжают на `Sheet`; поля ввода (input/textarea/чеклист) получают единый стиль вместо разрозненных `border-(--color-line)`.
- **Экран входа** (`App.tsx`) — та же стилистика `Button`/`Card`; единственный экран, до которого не доходили ни один из предыдущих планов.
- **Архив** (`ArchiveList.tsx`) — та же трактовка списка, что и колонка «Готово».
- Приоритет телефон/десктоп — одинаковый, оба входа используются владельцем поровну.

## Не входит в изменение поведения

Realtime-подписки, drag-and-drop логика (`onDragEnd`, `between()`), позиционирование, запросы к Supabase — без изменений. Это редизайн внешнего/интеракционного слоя, не бизнес-логики.
