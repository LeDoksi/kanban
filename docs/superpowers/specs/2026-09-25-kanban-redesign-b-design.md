# Канбан: редизайн «B» (KAN-115)

**Дата:** 2026-09-25
**Статус:** спека согласована в диалоге по секциям, ждёт ревью файла

## Цель

KAN-115: полный аудит дизайна и удобства и переосмысление интерфейса `web/` «на уровне лучших современных трекеров». Предыдущий редизайн (KAN-94, спека `2026-09-18-kanban-redesign-design.md`) дал токены, `Sheet`, `Button` и `motion`, но оставил главные проблемы удобства, в первую очередь на телефоне. Эта спека меняет раскладку, визуальный язык и все основные экраны. Данные, запросы к Supabase и логика позиционирования остаются прежними.

Выбранный масштаб: «переосмыслить», не «эволюция». Визуальное направление выбрано по эскизам (artifact «Три стиля для канбана»), вариант **B «Тёплый, но свой»**.

## Аудит: что не так сейчас

Сделан по живым скриншотам (телефон 390px и десктоп 1440px, обе темы, данные с доски).

1. **Телефон: пять колонок друг под другом.** Чтобы добраться до «В работе», нужно пролистать Hold и весь Backlog (в «Нашей вселенной» 28 карточек).
2. **Коробка в коробке.** Рамка колонки, внутри рамка эпика, внутри плашка карточки: три уровня вложенности съедают ширину и шумят.
3. **Заголовки эпиков** выглядят как подчёркнутые ссылки по центру и переносятся на 2-3 строки.
4. **Шапка.** Описание проекта занимает до трёх строк над доской, «40/78» без подписи, переключатель проекта не отличается от обычной кнопки.
5. **Карточки без ограничения высоты.** Длинный заголовок даёт карточку на пол-экрана. Номер `13` без префикса мало что говорит, «0/5» без иконки непонятно к чему.
6. **Палитра** кремовый `#fbf9f5` + жжёный оранжевый + кофейный текст: самое узнаваемое «ИИ-дефолтное» семейство (design-taste-frontend, раздел 4.2).
7. **Нет иконок.** Закрытие символом `×`, стрелки текстом.
8. **Модалка задачи.** Пять чипов статуса и три чипа типа одной кучей без иерархии. Редактирование «кликом по тексту» нигде не подсказано. Описания от агента в Markdown показываются сырыми.
9. **Выбранный проект не запоминается:** после перезагрузки всегда первый.
10. **Пустые колонки** на десктопе тянутся пустыми рамками на всю высоту.

Рынок: у мобильных канбанов стандартный приём — одна колонка на экран, соседняя видна краем, листание свайпом (Linear board view на Mobbin, обзоры mobile-first канбанов 2026). Общий тренд «спокойного софта» (Things 3, Linear): минимум рамок, иерархия типографикой, моушен только как обратная связь.

## Решения, принятые в диалоге

| Вопрос | Решение |
|---|---|
| Масштаб | Переосмыслить: новая раскладка, новый визуальный язык, новые карточка и шторка задачи |
| Стиль | B: холодный серый фон, терракотовый акцент, Onest, карточки без рамок на мягкой тени |

## Зависимости

Добавляются:

- `vaul`: шторка с физикой перетаскивания (снизу и справа).
- `@radix-ui/react-dropdown-menu`, `@radix-ui/react-popover`: меню статусов и выпадашки свойств, фокус и клавиатура из коробки.
- `@phosphor-icons/react`: иконки, одно семейство, начертание Regular.
- `@fontsource/onest`: шрифт локально, веса 400/500/600, подмножества cyrillic и latin.
- `marked` + `dompurify`: рендер Markdown в описаниях и комментариях с очисткой.

Бюджет прибавки к бандлу около 60-80 КБ gz. Размер измеряется до и после каждой фазы и записывается в отчёт фазы.

`motion` и `@dnd-kit/*` остаются. Решение KAN-94 «без веб-шрифта» отменяется: выбранный стиль держится на Onest, а локальная загрузка через `@fontsource` не ходит на сторонние хосты.

## 1. Визуальная система

### Цвет

Токены живут в `web/src/styles.css` (как сейчас: `@theme` для светлой темы и обычный `:root` в `@media (prefers-color-scheme: dark)` для тёмной). Старые токены (`panel`, `accent-soft` и т. д.) заменяются этим набором:

| Токен | Светлая | Тёмная | Роль |
|---|---|---|---|
| `ground` | `#eef0f2` | `#15171a` | фон страницы |
| `surface` | `#ffffff` | `#1f2327` | карточки, шторки, меню |
| `raised` | `#e4e7ea` | `#2a2e33` | активная вкладка, чипы, поля ввода |
| `ink` | `#1d2226` | `#eef0f2` | основной текст |
| `ink-2` | `#3a4148` | `#cdd2d7` | вторичный текст, заголовки закрытых задач |
| `muted` | `#66707a` | `#8c959e` | мета, подписи |
| `line` | `#dde1e5` | `#2c3136` | разделители и рамки полей |
| `accent` | `#c4532d` | `#e2744f` | главное действие, «Нужно от тебя», фокус |
| `on-accent` | `#ffffff` | `#15171a` | текст на акценте |
| `accent-soft` | `#f6e4dc` | `#3a2419` | фон карточек «Нужно от тебя» |
| `danger` | `#c0392b` | `#f07a6c` | баг, удаление |
| `overlay` | `rgb(29 34 38 / .40)` | `rgb(0 0 0 / .60)` | подложка шторок |
| `shadow` | `rgb(40 50 60 / .08)` | `rgb(0 0 0 / .45)` | тень карточек |

Баг и акцент близки по тону, поэтому баг всегда несёт иконку `Bug`, а не только цвет.

Контраст: каждая пара «текст на фоне» из таблицы (`ink`, `ink-2`, `muted` на `ground`, `surface`, `raised`, `accent-soft`; `on-accent` на `accent`; `danger` на `surface`) проходит WCAG AA 4.5:1. Проверка автоматическая (см. «Проверка»). Если пара не проходит, значение токена затемняется или осветляется, а не пара исключается.

### Типографика

Onest с фолбэком `ui-sans-serif, system-ui, sans-serif`. Шкала:

| Роль | Размер / вес | Где |
|---|---|---|
| title-lg | 20 / 600 | название проекта в шапке |
| title | 18 / 600 | заголовок в шторке |
| body | 15 / 400, line-height 1.4 | текст карточки, описание |
| meta | 13 / 500 | мета карточки, вкладки, подписи свойств |
| micro | 12 / 500 | счётчики, время комментариев |

Цифры везде `tabular-nums`. Поля ввода на сенсорных экранах остаются 16px (правило из KAN-114 сохраняется).

### Форма

| Элемент | Радиус |
|---|---|
| карточка, меню, popover | 16px |
| шторка снизу | 24px сверху |
| кнопки, вкладки, чипы | полный (pill) |
| поля ввода | 12px |

У карточек нет рамок, их отделяет тень `0 1px 2px var(--shadow), 0 4px 14px -6px var(--shadow)`. Рамки остаются только у полей ввода и разделителей внутри шторок.

### Иконки

Только `@phosphor-icons/react`, начертание Regular, размер 16/18/20 по месту. Символы `×`, `→`, `←` в разметке заменяются иконками (`X`, `ArrowRight` и т. д.).

### Моушен

Каждая анимация сообщает о событии. Все на пружинах `motion`, при `prefers-reduced-motion: reduce` заменяются мгновенными переходами (`useReducedMotion`).

- Карточка при смене статуса или порядка переезжает (`layoutId`, как сейчас).
- Индикатор активной вкладки переезжает пружиной (`layoutId` на плашке).
- Шторки: физика vaul.
- Нажатие на кнопку или карточку: `scale(0.98)`.
- Долгое нажатие: карточка приподнимается (тень сильнее, `scale(1.02)`), на Android `navigator.vibrate(10)`.

## 2. Каркас и навигация

### Шапка

**Телефон:** одна строка. Слева переключатель проекта (название title-lg + `CaretDown`, открывает шторку проектов), справа прогресс «40 из 78» (meta, `muted`). Описания проекта на доске нет, оно живёт в шторке проектов.

**Десктоп (≥1024px):** переключатель проекта, описание в одну строку с многоточием (клик открывает редактирование на месте, как сейчас), прогресс, кнопка «Новая задача» (primary) справа.

### Вкладки колонок (телефон и планшет, <1024px)

Прилипают под шапкой. Пять пилюль: Hold, Backlog, В работе, Нужно от тебя, Готово, у каждой счётчик (micro). Активная на плашке `raised`, плашка переезжает. Счётчик «Нужно от тебя» красится `accent`, если больше нуля. Ряд прокручивается горизонтально, активная вкладка подкручивается в видимую зону (`scrollIntoView({ inline: 'nearest' })`).

### Лента колонок (<1024px)

- Горизонтальный контейнер с `scroll-snap-type: x mandatory`, колонки шириной `calc(100% - 24px)` на телефоне (виден край соседней) и `calc(50% - 12px)` на планшете (768-1023px).
- Листание делает браузер. Своих обработчиков жеста на ленте нет.
- Синхронизация: тап по вкладке → `scrollTo` к колонке; прокрутка ленты → активная вкладка вычисляется по `scrollLeft` в обработчике `scrollend` (с фолбэком на `scroll` + `requestAnimationFrame`, где `scrollend` нет).
- Каждая колонка прокручивается по вертикали сама (`overflow-y: auto`, высота `100dvh` минус шапка и вкладки).
- Горизонтальный свайп карточки для смены статуса **удаляется** вместе с `swipe.ts` и его тестом: он конфликтует со свайпом ленты. Замена — меню статусов (раздел 3).

### Колонки на десктопе (≥1024px)

Пять колонок в сетке `grid-cols-5`, без внешних рамок. Колонка = заголовок (название meta + счётчик micro) + список карточек. Каждая колонка прокручивается сама, высота до низа окна. Drag-and-drop через `@dnd-kit` без изменений логики (`onDragEnd`, `between()`).

### Кнопка «Новая задача» на телефоне

Круглая кнопка 56px, фон `accent`, иконка `Plus`, внизу справа с отступом `16px + env(safe-area-inset-bottom)`. Открывает создание задачи. Задача создаётся в Backlog, как сейчас.

### Пустые колонки

Внутри списка по центру: иконка колонки (`muted`) и одна строка текста:

| Колонка | Текст |
|---|---|
| Hold | Здесь то, что отложено |
| Backlog | Новых задач нет |
| В работе | Сейчас ничего не в работе |
| Нужно от тебя | Когда Claude будет ждать твоего ответа, задача появится здесь |
| Готово | Закрытых задач пока нет |

На десктопе пустая колонка остаётся зоной сброса.

### Память

Новый модуль `web/src/prefs.ts` (чистые функции над `Storage`, каждое чтение и запись в `try/catch`):

- `lastProject` — id последнего открытого проекта. При загрузке: если он есть в списке проектов, открывается он, иначе первый.
- `lastColumn[projectId]` — последняя вкладка на телефоне.
- Стартовая вкладка без сохранённой: «В работе», если там есть задачи, иначе Backlog. Функция `startColumn(items, saved)` покрыта тестом.

### Загрузка и ошибки

- Пока идёт первая загрузка задач проекта: по три скелетона карточек в каждой колонке, в форме настоящей карточки, без мерцающего шиммера (при reduced-motion статичные).
- Ошибки Supabase показываются тостом (раздел 5), а не текстом в шапке.

## 3. Карточка, эпики, меню статусов

### Карточка

- Заголовок body, максимум три строки (`line-clamp-3`).
- Строка меты (meta, `muted`), показывается только то, что есть, в этом порядке:
  1. id `KAN-115`;
  2. тип: `Bug` + «баг» цветом `danger` или `Wrench` + «долг»; у задачи ничего;
  3. чеклист: `ListChecks` + «2/5»; когда всё отмечено, `CheckCircle` без счётчика;
  4. комментарии: `ChatCircle` + число;
  5. описание есть: `TextAlignLeft` без подписи.
- Комментарии считаются встроенным счётчиком в существующем запросе: `select('*, comments(count)')`. Тип `Item` получает поле `comments: { count: number }[]`.
- «Нужно от тебя»: фон `accent-soft`, кольцо `inset 0 0 0 1.5px var(--accent)`.
- «Готово»: заголовок `ink-2`, тень слабее.
- Drag-превью, скелетон и сама карточка используют одну разметку (`CardBody`), копий нет.

### Группы эпиков

Без рамок. Шапка группы — строка-кнопка на всю ширину: кольцо прогресса (14px, `accent`), название в одну строку с многоточием, «3/9» (micro), `CaretRight`. Тап открывает шторку эпика. Между группами 20px. Если в колонке есть и задачи эпиков, и задачи без эпика, перед вторыми подзаголовок «Без эпика» (meta). Пустые эпики в Backlog рисуются той же строкой.

### Меню статусов

Radix DropdownMenu, привязанное к карточке.

- Телефон: долгое нажатие 450 мс. Движение пальца больше 10px отменяет нажатие (это прокрутка). Логика порога — чистая функция в `web/src/longpress.ts` с тестом.
- Десктоп: правый клик по карточке или кнопка `DotsThree`, видимая при наведении и фокусе карточки.
- Пункты: пять статусов с иконками (текущий с галочкой), разделитель, «Открыть», «В архив» (только в «Готово»).
- Выбор статуса применяется сразу через существующий `setStatus`. Появляется тост «Перенесено в „<колонка>“» с кнопкой «Отменить» на 4 секунды; «Отменить» возвращает прежний статус и `position`.

### Колонка «Готово»

`DONE_SHOWN` (5) остаётся. Внизу кнопка-пилюля «Архив · N» (N = скрытые закрытые + архивные), открывает шторку архива.

## 4. Шторка задачи и шторка эпика

### Контейнер `Sheet`

`web/src/ui/Sheet.tsx` переписывается на vaul:

- `<1024px`: `Drawer` снизу, высота 92% (`snapPoints` не используются), ручка сверху, закрытие стаскиванием, тапом по подложке, Esc. Учёт `visualViewport` из KAN-112 сохраняется.
- `≥1024px`: `Drawer` с `direction="right"`, ширина 480px, подложка `overlay`.
- Для окна по центру (создание задачи на десктопе) остаётся нынешняя реализация `placement="center"` на `motion`: vaul не умеет центрированный режим, а отдельный Radix Dialog ради одного окна не нужен. Esc и клик по подложке закрывают, как сейчас.

### Шторка задачи (TaskModal → TaskSheet)

Сверху вниз:

1. **Строка действий.** `KAN-115` моноширинным `muted` (тап копирует id, тост «Скопировано»). Справа `DotsThree` с пунктами «В архив» (если «Готово»), «Вернуть в работу» (если в архиве), «Удалить». Удаление подтверждается вторым шагом в том же меню («Удалить навсегда?» + кнопка `danger`), `window.confirm` уходит. На десктопе рядом `X`.
2. **Заголовок.** Всегда поле ввода (`textarea` с автовысотой), стилизованное как текст title; подложка `raised` при наведении и фокусе. Сохранение по blur и Enter, как сейчас.
3. **Свойства.** Строки «подпись (meta, `muted`) — значение». Значение — кнопка, открывающая Radix Popover со списком:
   - Статус (иконка + название).
   - Тип (задача / баг / долг).
   - Эпик (список `selectableEpics` + «Без эпика»); рядом кнопка `ArrowSquareOut` «Открыть эпик», всегда видимая.
   - Блокирует (только если `blocks` не пуст): чипы id.
4. **Описание.** Рендер Markdown (`marked` → `DOMPurify.sanitize`; ссылки получают `target="_blank" rel="noopener noreferrer"`). Кнопка «Изменить» переключает в `textarea` с сырым текстом; сохранение по blur и `Ctrl/Cmd+Enter`. Пустое описание: плейсхолдер «Добавить описание» (тап сразу открывает поле).
5. **Чеклист.** Заголовок «Чеклист · 2 из 5», круглые чекбоксы, выполненные зачёркнуты `muted`. Поведение `toggleCheck` без изменений. Добавления пунктов нет.
6. **Комментарии.** Лента: автор («Claude» / «Ты»), относительное время (`relTime()` в `web/src/time.ts`: «только что», «5 мин назад», «2 ч назад», «вчера», дальше дата; полная дата в `title`), текст в Markdown тем же рендером. Поле ввода прилипает к низу шторки, отправка кнопкой `PaperPlaneRight` или Enter. Защита от двойной отправки (`sending`) сохраняется.

Все ошибки внутри шторки идут в тосты.

### Шторка эпика (EpicModal → EpicSheet)

Тот же контейнер. Название (title), цель в Markdown, кольцо прогресса 48px с «3 из 9», список задач эпика строками, сгруппированными по статусу в порядке колонок. Строка: иконка статуса, заголовок в одну строку, id. Тап открывает шторку задачи.

## 5. Остальные экраны и общие компоненты

- **Создание (CreateModal).** `<1024px` шторка снизу, `≥1024px` окно по центру 480px. Сегментный переключатель «Задача / Эпик». Поле заголовка в фокусе сразу. `guessType` сохраняется; угаданный тип подсвечивается чипом, тап по чипу меняет тип. Эпик выбирается тем же Popover. Кнопка во всю ширину «Создать в Backlog» (для эпика «Создать эпик»). `Ctrl/Cmd+Enter` отправляет.
- **Проекты (ProjectDrawer).** `<1024px` шторка снизу, `≥1024px` слева. Строка: название, описание в одну строку, кольцо прогресса. Текущий с галочкой. `DotsThree` на строке: «Изменить описание», «В архив». «Новый проект» внизу, форма NewProject открывается шагом внутри шторки.
- **Архив (ArchiveList).** Шторка, поле поиска по заголовку сверху (фильтр на клиенте), строки с кнопкой «Вернуть».
- **Вход (SignIn).** По центру: «Канбан» (title-lg), строка «Личная доска задач по проектам» (`muted`), кнопка «Войти через Google» с `GoogleLogo`.

## Проверка

- `cd web && npm test`. Тест `swipe.test.ts` удаляется вместе с `swipe.ts`. Новые тесты: `prefs.test.ts` (`startColumn`, чтение и запись с падающим `Storage`), `longpress.test.ts`, `time.test.ts` (`relTime`), `markdown.test.ts` (вырезается `<script>` и `onerror`, ссылки получают `target` и `rel`), `contrast.test.ts` (все пары токенов из раздела 1 ≥ 4.5:1 в обеих темах; токены читаются из `styles.css`).
- `npm run lint`, `npm run build`, размер `dist/assets` до и после каждой фазы.
- Скриншоты тем же способом, что при аудите (Playwright, фейковая сессия, подмена REST-ответов снимком данных доски): 390×844 и 1440×900, обе темы, доска, шторка задачи, шторка эпика, создание, проекты, архив, вход. Снимки «до» и «после» прикладываются к отчёту.
- Проверка на живом телефоне делается владельцем: долгое нажатие, шторка, клавиатура, свайп ленты. Каждая фаза деплоится отдельно, чтобы её можно было проверить.

## Фазы

Каждая фаза — отдельный PR и деплой; между фазами приложение рабочее.

1. **Основа.** Токены B, Onest, Phosphor, `Button`, тосты. Старые экраны перекрашиваются и получают иконки без смены раскладки.
2. **Каркас.** Шапка, вкладки и лента на телефоне, колонки на десктопе, `prefs.ts`, пустые колонки, скелетоны. Свайп карточки удаляется и в той же фазе заменяется меню статусов по долгому нажатию и правому клику (`longpress.ts`, тост с «Отменить»): иначе между фазами на телефоне не было бы быстрой смены статуса, а свайп карточки конфликтовал бы со свайпом ленты.
3. **Карточка.** `CardBody`, мета со счётчиком комментариев, группы эпиков, кнопка «Архив · N».
4. **Шторки.** `Sheet` на vaul, шторка задачи с Markdown, шторка эпика.
5. **Остальное.** Создание, проекты, архив, вход; финальный проход по контрасту и reduced-motion; снимки «до/после».
